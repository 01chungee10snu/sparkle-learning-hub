# 생명 연못 v34 · 전체 응답 기록

2026-10-21

## 적용한 경험

연못 배경 1장과 연못 물고기 24종을 새 원화로 교체했다. 바다 40종의 기존 그림은 유지한다. 개별 원화의 생성 프롬프트·크기·해시는 `assets/pond-originals-v34/manifest.json`에 있다.

연못 화면에서 물고기에게 인사하기, 누른 물결 따라오기, 먹이 반응, 방향 전환, 천천히 헤엄치기와 거품·물결 반응을 제공한다. 모션 줄이기를 지원한다. 시작 전 미리보기와 쉬는 화면에서는 상호작용과 애니메이션을 멈춘다.

## 시간과 배움 재료

| 프로필 | 한 방문 주기의 최대 활동시간 | 다음 방문 전 새 문항 | 최소 과목 수 |
| --- | ---: | ---: | ---: |
| 세희 | 3분 | 3개 | 2과목 |
| 태희 | 5분 | 5개 | 3과목 |

- 실제 연못 활동시간이 누적 1분을 채울 때마다 수정·꽃잎·깃털·먹방울 중 잔액이 있는 재료 1개를 차감한다. 재료 종류를 순환하고 음수 잔액은 허용하지 않는다.
- 시작 버튼 이후에만 시간이 흐른다. 일시정지, 화면을 떠남, 숨겨진 탭, 60초 동안 입력이 없는 상태에서는 시간과 애니메이션이 멈춘다. 절전·백그라운드 지연을 뒤늦게 청구하지 않는다.
- 짧은 방문도 누적하며 새로고침으로 시간을 되돌릴 수 없다. 동일 기기 내 같은 아이의 중복 탭 방문을 Web Locks와 임시 소유권 기록으로 제한한다.
- 최대시간 또는 재료 소진 후에는 배움 산책으로 이어진다. 새 문항과 과목 분배가 조건이며 오답·힌트를 사용한 참여도 인정한다. 이미 풀었던 문항 및 같은 한자 글자의 변형으로 참여 수를 반복해서 채울 수 없다.
- 배움 산책을 마치면 다음 방문 한 차례에 필요한 최소 재료(총 3개 또는 5개)까지 부족분만 보충한다. 정답 보상과 구분한 회차별 영수증으로 중복 지급을 방지한다. 동물의 상태를 악화시키는 벌은 없다.
- 처음 문제를 고를 때 남은 적합 문항 수가 정말 적으면 완료 가능한 수로 줄인다. 새 문항이 없으면 내용 확장이 필요하다는 안내를 표시하며 자동 보충을 반복하지 않는다.

규칙은 `platform/pond-session.js`의 `POND_RULES`, 재료 비용과 보충은 `platform/resource-economy.js`에 있다. 여러 기기가 오프라인으로 동시에 방문하는 상황은 나중에 기록을 병합하는 방식이며 서버의 실시간 전역 잠금은 아니다.

## 편중을 줄이는 출제와 IRT

과목 분배를 먼저 정하고, 허용된 연령·단계 안의 아직 풀지 않은 문항을 고른다. 현재 과목 IRT 추정치에 대한 예상 정답확률을 기준으로 적합한 난이도를 찾는다. 비슷하게 적합한 후보에서는 최근 덜 연습한 개념을 우선한다. 한 과목의 문제 수나 반복 정답만으로 다음 방문 조건을 계속 채울 수 없다.

기존 IRT는 편집자가 정한 초기 난도와 추측 모수를 사용하는 잠정 Bayesian 1PL 형식이다. 이번 작업으로 실증 보정된 문항 모수나 표준화 점수가 생기는 것은 아니다. 최초 독립 응답만 능력 추정 근거로 사용하며 힌트·해설 후 재시도, 놀이시간, 재료 잔액은 능력치를 높이지 않는다.

## 전체 응답 기록

기존 문항별 최근 5회 기록은 화면·진행 상태용으로 유지한다. `platform/response-log.js`는 별도로 모든 새 제출, 힌트, 해설 후 재시도를 저장한다.

저장 필드: 아이의 내부 별칭, 이벤트/세션/게임/문항 ID, 문항 내용 버전, 과목·개념, 제출 답, 정오답, 도움 여부, 최초 독립 응답 여부, 문항 표시·제출 시각, 경과시간, 당시 난이도·추측 모수, IRT 추정 전후 값과 모델 버전. 문항별 제출 순번은 **해당 기기 기준**이며 기기 간 절대 순서를 뜻하지 않는다. 경과시간은 최대 10분으로 제한한 벽시계 시간이고 연못의 활동시간과 다르다.

답을 처리하기 전에 동기식 임시 기록을 남긴 다음 IndexedDB로 옮긴다. 전송 실패 시 원본과 미전송 목록을 보관하며 서버가 정확한 이벤트 ID 목록을 확인해 준 경우에만 미전송 표시를 해제한다. 확인 후에도 로컬 원본을 지우지 않는다. 새 전체 이력은 배포 이후부터 누적되며, 과거에 5회 제한으로 이미 사라진 응답은 복구하지 않는다.

## 기존 Supabase 재사용

기존 가족 연결을 재사용한다. 신규 migration은 `supabase/migrations/20261021000800_learning_response_events.sql`이다. `magic_response_events`와 `magic_family_append_responses`를 추가하고, 기존 물고기 이력의 허용 종을 64종으로 확장한다.

가족 코드를 서버에서 검증하고 그 가족의 학습자 ID를 찾는다. 클라이언트가 다른 학습자의 UUID를 지정하지 않는다. 테이블의 익명 직접 읽기·쓰기는 차단하고 가족 범위의 RLS를 적용한다. 동일 이벤트의 재전송은 한 번만 저장되며 동일 ID에 다른 내용을 붙이면 거절한다. 서비스 역할 키는 브라우저에 넣지 않는다.

연못 시간·재료 영수증은 기존 가족 스냅샷과 함께 병합한다. 전체 응답 로그는 작은 이벤트 묶음으로 따로 보낸다. 보호자 화면에서 학습 요약 동기화와 전체 응답 전송 상태를 구분한다. 이후 IRT 보정용 분석에서는 클라이언트의 `independentFirst` 값만 믿지 않고 학습자·문항 버전별 실제 첫 응답을 다시 식별해야 한다.

## 검증

- `npm run check:pond`: 시간·비용·일시정지·재접속·중복 탭·과목 분배·모든 응답 로그의 회귀 검사.
- `node scripts/qa-pond-v34.mjs`: 실제 브라우저의 320×568, 390×844, 768×1024 화면에서 시작/상호작용/자동 정지/학습 복귀/전부 오답인 경우/재접속을 검증한다. 합성 프로필만 사용한다.
- `node scripts/qa-response-log.mjs`: 실제 IndexedDB의 12건 보관, 새로고침 후 보존, 일부 전송 확인 후 전체 이력 12건 및 미전송 9건 보존을 검증한다.
- 전체 회귀 검사는 `npm run check`로 실행한다.
