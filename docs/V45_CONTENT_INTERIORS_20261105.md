# 마법마을 v45 — 학습·놀이 내부 콘텐츠의 Blender 기반 개편

작성일: 2026-11-05 (한국 시간). 외형 개선만 반복하지 않고, 기존 활동을 수행하는 내부 공간과 조작 화면을 실제 제작 자산으로 개편했다. 최종 공개 여부는 `qa-interiors-v45/deployment.json`의 실측 결과로 구분한다.

## 1. 구현 범위

**Blender에서 직접 제작한 내부 공간 13종과 소품 32종을 Unity에 적용했다.** 마을에서 학습 또는 놀이를 열면 같은 Unity 실행 환경 안에서 해당 공간으로 전환된다. 문제·보기·입력·설명은 선명한 실시간 글자로 유지하고, Blender 제작 프레임·소품·피드백과 함께 구성한다.

| 공간 | 실제 제작한 내부 요소 | 기존 기능 연결 |
|---|---|---|
| 수학 공방 | 주판, 저울, 자, 입체 블록, 책상 | 수학 문제·수량 놀이·숫자 입력 |

| 한자 수련관 | 두루마리, 붓, 먹, 대나무 | 한자의 음·뜻과 기존 학습 |

| 연못 관찰실 | 연못·물가·부두·수초 | 보유 물고기, 돌봄, 체류 시간·재료 규칙 |
| 바다 탐험실 | 물가·현창·지구본·조개 | 해양생물 목록·관찰·해금 |

| 발견의 기록실 | 성취 전시와 기록 소품 | 기존 성장 기록과 단계 선택 |
| 마법마을 안내실 | 책장과 안내 책상 | 모험 지도·학습 추천·친구·공용 안내 |

소품 32종은 주판·저울·책·붓·트로피·보물상자·씨앗·별·물뿌리개 등의 도구와, 고양이·강아지·토끼·물고기·딸기·바나나·당근·컵·공·나무 등 직접 만든 학습 사물을 포함한다. 총 45개의 FBX와 대응 Unity Prefab을 사용한다.

## 2. 학습 내용 자체의 표현

- 등록된 사물 그림이 제시되는 문제에서는 원래 사물의 의미를 보존하는 Blender 소품을 표시한다. 영어 그림 문제의 고양이는 실제 Unity 책상 위 3D 고양이와 같은 모델의 투명 렌더 이미지로 연결된다.
- 수량 그림은 명시적으로 대응되는 사물만 교체한다. 개수·순서·문항 ID·정답은 바꾸지 않는다. 해석이 불확실한 그림·문구는 원본을 유지한다.
- 힌트는 기존 서버/호스트 응답을 받은 뒤 등불, 정답·학습 피드백은 별 또는 새싹으로 표현한다. 연출이 별을 추가하거나 정답을 판정하지 않는다.
- 보상 화면·보기·숫자 키패드·활동 카드·도감·상점에 같은 목재·양피지·금속 장식 프레임을 적용했다.
- 별도 학습 페이지에도 동일한 내부 공간 렌더와 소품·프레임을 적용했다. 도입 화면만 바꾸고 문제 화면은 그대로 두는 구성에서 벗어나도록 했다.

**구현 경계:** 모든 텍스트를 3D 메시로 바꾸지는 않았다. 작은 화면의 읽기·음성·키보드·보조기술 접근성을 위해 문제와 보기는 기존 DOM 입력 체계를 사용한다. 내부 공간과 학습 사물은 실제 Unity 메시이고, DOM 장식은 동일한 Blender 모델의 직접 렌더링 결과다. 임의 생성 이미지를 배경으로 덮은 것이 아니다.

기존 요정·NPC 원화, 경시대회 원본 문항 이미지, 직업별 기존 일러스트, 수집한 생물의 개별 원화는 유지했다. 모든 캐릭터와 64종 생물을 새 3D 모델로 전환했다고 주장하지 않는다. 온실·책상 등 모든 장식 소품이 독립 미니게임인 것도 아니다.

## 3. 화면 구성과 성능 처리

태블릿 가로에서는 왼쪽에 실제 내부 공간, 오른쪽에 큰 학습 작업판을 배치한다. 세로 화면에서는 위에 공간, 아래에 작업판을 배치한다. 기존 마을 HUD는 활동 중 숨기며, 긴 문항·도감은 글자를 줄이거나 자르지 않고 작업판 안에서 스크롤한다.

한 번에 내부 공간 하나만 생성하고, 활동을 닫으면 제거하여 마을 카메라로 복귀한다. 별도의 두 번째 WebGL 실행기를 추가하지 않았다. 가벼운 2D 모드와 별도 학습 페이지에서는 실제 모델을 렌더링한 WebP/PNG를 사용한다. '움직임 줄이기' 설정을 존중한다.

가독성 기준은 보기 글자 최소 20px, 응답 터치 높이 최소 48px로 브라우저에서 측정한다. 장식의 크기보다 실제 읽기·입력 영역을 우선한다.

## 4. 검증 근거

- `interior-audit.json`: Unity 내 13개 내부 공간 생성·복귀, 잘못된 공간 키 거부, 개인/가족 마을 × 두 학습자의 44개 기존 목적지 경로 검사.
- `interaction-qa.json`: 360×740 세로 및 844×390 가로의 실제 숫자 키패드 입력·지우기·제출, 짝 선택, 수량 증감, 사물 개수·응답 인덱스·이벤트 보존 검사.
- `browser-interiors-qa.json`: 독립 Chromium 환경에서 실제 공간 전환, 학습 응답, 피드백, 마을 복귀 후 건물 재터치, 작은 화면 배치, 2D 대체 화면 검사.
- `webgl-build-manifest.json`: 최종 Unity 실행 파일 4개의 크기·SHA-256.
- `protected-source-hashes.json`: 개편 전 운영 버전과 핵심 학습·IRT·보상·동기화·연못 규칙 코드의 일치 확인.
- 전체 `npm run check`, 기존 학습 3/5문항 완료, 지도/입장 화면 및 클라우드 병합 모의검사는 별도 로그로 보존한다.

검수 중 컴파일 이름 충돌, 직업 탐색관의 전체화면 CSS 충돌, 내부 화면에 남던 외부 HUD, 책상과 학습 사물의 높이 불일치를 수정했다. 기존 이미지 검사도 다운로드 완료를 기다린 뒤 확인하도록 보완했다. 완료 화면에서는 일반 일시정지 버튼 대신 기존 전용 ‘마을로 돌아가기’를 사용하도록 검증 흐름을 수정했다. 적응형 문항 은행은 같은 게임 안에서도 보기 선택·조작형 문제가 섞이므로 실제 응답을 통해 해당 조작 유형에 도달하도록 추가 검사를 구성했다.

**검증 한계:** Chromium 터치 에뮬레이션 및 소프트웨어 WebGL 검사이며 물리적 iPad·갤럭시의 Safari/GPU·발열·메모리·실측 FPS 검증은 아니다. 클라우드 기록 검사는 모의 RPC다. 브라우저 시험은 새 합성 학습 상태에서 수행하고 운영 Supabase 요청을 차단한다. 실제 가족 기록에 시험 답안을 쓰지 않는다.

`games/`, `platform/progress.js`, `platform/irt.js`, `platform/rewards.js`, `platform/cloud-sync.js`, `platform/resource-economy.js`, `platform/pond-session.js`, `platform/play-balance.js`, `supabase/`의 기존 학습/경제/저장 권한은 변경하지 않는다. 실제 아이들의 학습이력·재화·물고기를 초기화하지 않는다.

새 내부 자산은 v44의 원본 Blender 기하·정점 차폐 제작 함수를 재사용한 직접 제작물이다. 사용자가 제시한 기준 이미지는 품질 방향으로만 참고했고 게임 배경이나 배포용 파일로 포함하지 않았다. 기존 외부 자산의 출처·라이선스는 유지한다.

- 공개 웹 소스: `feat/interior-world-v45-20261104`, `unity-v45/export_interiors.py`, 콘텐츠 연결 JS/CSS, 직접 렌더링한 이미지와 검증 자료.
- 비공개 Unity 소스: 동일 브랜치, `Assets/Art/InteriorsV45`, `Assets/Prefabs/InteriorsV45`, `VillageInteriorStage`, 편집 원본 `SourceArt/InteriorsV45/interior-sets-v45.blend`.
- 공개 저장소에는 비공개 Unity C#·FBX·Prefab·Blender 원본을 복사하지 않는다.

```sh
blender -b --factory-startup --python unity-v45/export_interiors.py -- /path/to/unity-v45
# Unity batch entry: VillageInteriorBuild.PrepareAndBuild
# 다음 명령은 Unity 빌드가 종료된 후에만 실행
python3 scripts/sync-interior-v45.py /path/to/unity-v45
npm run check
INTERIOR_QA_ORIGIN=http://127.0.0.1:4655 npm run qa:interiors:v45
```

최종 배포 상태와 운영 주소 검증은 [배포 기록](qa-interiors-v45/deployment.json)에 별도로 보존한다. 배포 확인 전에는 개발본 완료와 운영 반영을 구분한다.
