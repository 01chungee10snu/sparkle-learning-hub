# 보호자 학습 대시보드 · 개인화 기억 모델 v14 — 2026-10-15

## 1. 목적

마법 마을의 보호자 화면은 별·접속일·플레이시간보다 다음 학습 증거를 우선한다.

- 독립 회상 성공률
- 오답 후 다음 독립 시도의 회복률
- 힌트 사용 비율
- 전이(transfer) 목적 문항 성공률
- 2/4/7/14/30일대 지연회상률
- 현재 복습 대기 문항
- 과목별 IRT 추천 근거 수와 불확실성
- 과목별 개인화 복습 활성 여부

형제 간 순위·비교 점수는 만들지 않는다.

## 2. 개인화 기억 모델

### 원자료

`platform/memory-model.js`는 각 문항의 독립 시도 중 다음 조건만 사용한다.

1. 이전 독립 시도가 정답이어야 한다.
2. 다음 독립 시도까지 최소 0.25일 이상 경과해야 한다.
3. 힌트 사용(`assisted=true`) 시도는 제외한다.
4. 문항의 과목/guessing 정보는 IRT bank에서 읽는다.

즉, 같은 날의 즉시 재도전은 forgetting curve에 포함하지 않는다.

### 추정

기억 유지 확률의 기본 형태:

`P(correct after d days) = c + (1-c) * 0.5^(d / H)`

- `c`: IRT 문항의 guessing 보정값
- `d`: 지연 일수
- `H`: 개인·과목별 기억 반감기(half-life)

기본 반감기는 7일이며 sparse data에서 극단값을 피하도록 log prior를 둔다.

### 개인화 활성 gate

다음 두 조건을 모두 만족해야 실제 복습 간격을 변경한다.

- 지연회상 관측 `n >= 6`
- 관측된 최대 지연 `>= 2일`

조건 미충족 시 factor는 정확히 `1.0`이며 기존 `2→4→7→14→30일`을 사용한다.

활성 후에도 factor는 `0.65~1.60`으로 제한한다.

- 기억 유지가 약하면 간격을 최대 35% 단축
- 유지가 강해도 최대 60%까지만 확장

개인화 interval = `기본 interval × factor`, 0.5일 단위로 반올림한다.

이 모델은 학업능력·IQ·발달 진단이 아니다.

## 3. 학습 목적 메타데이터

새 학습 회차와 attempt에는 아래 목적을 기록한다.

- `foundation`
- `review`
- `challenge`
- `transfer`

문항 선택 전략은:

- `adaptive`
- `review`

보호자 대시보드의 전이 성공률은 `purpose=transfer`인 독립 시도만 계산한다.

기존 기록에는 purpose가 없으므로 과거 활동을 임의로 전이 기록으로 소급 분류하지 않는다.

## 4. 보호자 대시보드 UI

`보호자 대시보드`에서 태희·세희를 탭으로 전환한다.

탭 전환은 **조회 대상만 바꾸고 현재 플레이 중인 학습자 프로필을 변경하지 않는다.**

상단 KPI:

- 독립 회상
- 오답 회복
- 힌트 사용
- 전이 성공

과목별 카드:

- 개인화 활성/기본 간격
- 기억 반감기
- 독립 회상률
- 지금 복습할 문항 수
- 오답 회복률
- 약 2/4/7/14/30일 지연회상률
- IRT 추천 근거 수와 불확실성
- 관찰할 skill

다가오는 복습에는 문항의 게임·skill과 `지금/오늘/N일 후`를 표시한다.

## 5. 보호자 행동 추천

대시보드 recommendation은 진단이 아니라 학습 상호작용 제안이다.

예:

- 복습 대기가 있으면 정답 제시 전 스스로 떠올릴 시간 제공
- 힌트 의존이 높으면 첫 10초 동안 문제를 자기 말로 다시 표현
- 오답 회복이 낮으면 같은 날 반복보다 다음 날 짧게 재인출
- 전이 기록이 적으면 집의 물건/다른 이야기에서 적용 질문
- 개인화 표본이 부족하면 기본 간격 유지 안내

## 6. Cloud persistence

개인화 모델 결과 자체는 DB에 저장하지 않는다.

영속화할 것은 원자료다.

- correct
- assisted
- answered_at
- purpose
- strategy
- game/question/round id

Migration:

`db/migrations/202610150002_learning_personalization_dashboard.sql`

이렇게 하면 추후 모델이 개선되어도 과거 원자료로 대시보드와 복습 스케줄을 재계산할 수 있다.

## 7. 검증 기준

- 강한 지연회상 예시: 8일 뒤 6회 성공 → 개인화 활성, factor > 1
- 약한 지연회상 예시: 2일 뒤 6회 실패 → 개인화 활성, factor < 1
- 표본 부족 → factor = 1
- transfer purpose가 backup/import 후에도 보존
- 모바일 390×844 / 데스크톱 1440×900 대시보드 overflow 없음
- 대시보드에서 세희를 조회해도 현재 플레이 learner는 태희로 유지
- 기존 55 games / 4,828 items / IRT / reward / sibling isolation 회귀 PASS
