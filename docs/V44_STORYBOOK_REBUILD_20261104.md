# 마법마을 v44 — 실제 플레이 공간의 동화풍 그래픽 개편

작성·검증일: 2026-11-04. 사용자가 제공한 마을 이미지는 **미술 품질 기준**으로만 사용했다. 새 이미지를 생성하거나 기존 장면 위에 그림 한 장을 덮은 것이 아니라, Blender의 실제 모델과 Unity 렌더링·배치·카메라를 수정했다.

## 결과

이번 버전은 소품 개수를 늘리는 확장이 아니라 **주요 시각 체계를 교체한 버전**이다. 무지개 배움성, 기와집, 둥근 수목, 시장, 광장과 연결 도로가 실제 Unity 장면에서 보인다. 기존 문제풀이·학습자 분리·보상·물고기 돌봄·정원 기능은 유지한다.

| 기준 이미지에서 채택한 특징 | 실제 구현 |
|---|---|
| 둥근 중심 성과 여러 탑 | 중앙 무지개 배움성, 둥근 벽체·소탑·계단·깃발·아치문, 기존 academy 학습 진입 연결 |
| 다채로운 비늘 지붕 | 곡면에 배치한 개별 입체 기와, 다색 첨탑, 기와가 겹치던 초기 결함 수정 |
| 완성된 집의 세부 표현 | 폐쇄된 벽체, 박공지붕·개별 기와·처마·굴뚝·아치 창문·문손잡이·목재 테두리·화분 |
| 부드러운 표면과 깊이 | 모서리 다듬기, 부드러운 법선, Blender에서 계산한 주변 차폐를 정점 색상에 저장, 접지 그림자와 광원 조정 |
| 정리된 마을 구성 | 중앙 광장, 실제 이동 경로를 따른 연결 도로, 시장과 주거지 배치, 화단과 울타리형 관목 |
| 물길과 다리 | 기존 이동 가능한 영역 바깥의 외곽 하천·강둑·물결·아치 다리. 외곽 장식 다리를 새로운 통행 가능 지역으로 주장하지 않음 |
| 화면 전체의 일관성 | 시작 화면·과목·지도 아이콘을 실제 Unity 모델 렌더링으로 교체. 예전 v41의 저해상도 Three.js 미리보기는 활성 화면에서 제거 |

**기준 이미지와 동일한 품질을 달성했다고 단정하지 않는다.** 이미지의 고정 구도·풍부한 배경 장식과 실시간 모바일 플레이 화면은 차이가 있다. 이번 구현은 실제 모델·명암·중심 구도·건물 세부 표현을 그 방향으로 크게 수정한 것이며, 게임의 모든 NPC를 새 3D 캐릭터로 만든 것은 아니다. 기존 태희·세희 요정 및 NPC 원화는 보존했다.

## 검증

| 검사 | 실제 결과 |
|---|---|
| Unity WebGL 빌드 | Succeeded, 빌드 보고서 오류 0·경고 0 |
| 에디터 장면 | 개인 마을·가족 광장 × 태희·세희 4개 장면, 11개 목적지씩 44개 경로 검사 |
| 신규 모델 사용 | 브라우저 개인 마을에서 새 정점 차폐를 갖춘 고도화 모델 인스턴스 84개 확인 |
| 태블릿 1024×768·휴대전화 390×844 | 현재 Unity 버전과 실제 메시 확인, 3D 건물 직접 터치, 문제 응답, 연못·정원, 기존 자유 산책 검사 통과 |
| 움직임 | 기존 풍차·물레방아 등의 회전과 움직임 줄이기 검사 통과. 느린 프레임에서도 전환 즉시 정지하도록 수정 |
| 웹 입장·지도 | 3개 화면 크기에서 학습자 전달·그림 로딩·접근 가능한 지도 유지 검사 통과 |
| 기존 2D 학습 | 태희 5문항·세희 3문항 완료 및 다음 학습 검사 통과 |
| 학습·놀이 회귀 | 전체 정적 검사 통과. 8,462개 문항·정답·IRT 무결성 및 보상·돌봄 로직 포함 |
| 가족 기록 병합 | 독립 모의 기기 2개, 동시 충돌 2건, 합성 학습 시도 5건과 재시도·중복 방지 통과 |

웹 실행본에서 발견한 `Unlit/Color` 재질 누락은 Unity 리소스로 명시적으로 포함해 해결했다. 첫 브라우저 검사에서 확인한 준비 신호 실패를 숨기지 않고 수정 후 다시 검사했다. 최종 검증 대상 바이너리는 `qa-unity-v44/webgl-build-manifest.json`의 네 파일 해시와 일치한다.

**검증 한계:** 물리적 갤럭시·iPad의 GPU·Safari·발열·메모리·실측 FPS는 아직 검증하지 않았다. 테스트는 Chromium 터치 에뮬레이션과 소프트웨어 WebGL이다. 그림자 지도는 작은 화면에서 끄고, 모델의 사전 계산 명암과 접지 그림자를 유지한다. 큰 화면에서도 기와 표면의 자기 그림자 떨림을 피하도록 사전 계산 명암을 우선한다. 이 정책을 성능 수치 보장으로 해석해서는 안 된다.

기록 검사는 모의 서버이며 실제 가족 데이터의 운영 서버 승계를 직접 시험하지 않았다. 모든 브라우저 검사에서 운영 Supabase 통신을 차단했다.

## 데이터·소스 보존

이번 작업에서 `games/`, `platform/progress.js`, `platform/cloud-sync.js`, `platform/irt.js`, `platform/rewards.js`, `supabase/`를 수정하지 않았다. 실제 아이의 기록·별·물고기 수집 상태를 초기화하거나 이관하지 않았다. 시각 자산의 변경과 학습 상태의 권한을 분리했다.

Blender 원본, FBX 20개, Unity Prefab·Shader·C#는 비공개 `sparkle-fairy-village` 저장소에 보존한다. 공개 `sparkle-learning-hub`에는 새 실행 파일·직접 렌더링한 웹 이미지·제작 스크립트·검증 자료만 둔다. 사용자 제공 참고 이미지를 게임 배경이나 재배포 에셋으로 포함하지 않았다.

현재 그래픽 제작 스크립트: `unity-v44/export_storybook.py`.

```sh
npm run check
npm run check:storybook:v44
NATIVE_QA_ORIGIN=http://127.0.0.1:4644 npm run qa:storybook:v44
READABLE_QA_ORIGIN=http://127.0.0.1:4644 npm run qa:refactor
CLOUD_QA_ORIGIN=http://127.0.0.1:4644 npm run qa:cloud:canonical
```

로컬 구현·Unity 빌드·브라우저 통합검증 완료. 운영 반영 여부와 공개 주소의 실제 응답은 `qa-unity-v44/deployment.json`에 별도 기록한다. 해당 파일에 확인 결과가 기록되기 전에는 배포 완료로 해석하지 않는다.
